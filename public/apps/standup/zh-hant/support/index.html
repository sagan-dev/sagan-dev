支援

以下是常見問題的解答。仍然無法解決？請發送電子郵件與我們聯絡。

如何第一次連接我的桌子？
  1. 先將桌子與其他裝置斷開連線——例如關閉手機上的桌子控制應用程式。桌子一次只能與一個裝置通訊。
  2. 開啟配對模式：按住桌子控制器上的藍牙按鈕約 3 秒，直到藍色指示燈開始閃爍。
  3. 開啟 Standup，並在 macOS 詢問時允許使用藍牙。
  4. Standup 會自動找到桌子並完成連線——彈出面板會先顯示「Connecting…」，接著顯示桌子的名稱。Mac 上不需要任何額外的配對步驟。

此後，每次啟動應用程式或 Mac 喚醒後，Standup 都會自動重新連線。

Standup 找不到我的桌子

請依序嘗試以下步驟：

  1. 關閉所有其他已連線到桌子的應用程式（手機應用程式、另一台 Mac 等）。桌子一次只能與一個裝置通訊。
  2. 在系統設定 → 隱私權與安全性 → 藍牙中允許 Standup 使用藍牙。
  3. 確認藍牙中顯示的桌子名稱仍包含「Desk」這個字。
  4. 開啟配對模式：按住控制器上的藍牙按鈕約 3 秒，直到指示燈閃爍。
  5. 重設桌子：將桌子降到最低位置，按住降下按鈕直到桌子先降後升，接著按住控制器上的藍牙按鈕直到指示燈閃爍，然後重新開啟 Standup。
如何使用 Outlook 會議？

Standup 讀取的是 macOS 的「日曆」。請在系統設定 → 網際網路帳號中新增你的 Outlook、Exchange 或 Microsoft 365 帳戶，並確認該帳戶已開啟「日曆」。之後該帳戶就會出現在「日曆」應用程式中，Standup 也就能看見其中的會議。當 Standup 要求日曆存取權限時，請予以允許。

哪些會議會讓桌子升起？

有其他與會者、在網址、地點或備註中含有線上會議連結（Teams、Meet、Zoom、Webex、Whereby 或 GoToMeeting），且是你主辦或已接受的會議。全天事件、已取消、已拒絕、暫定或未回覆的邀請，以及標記為「空閒」的事件都會被忽略。桌子會在開始前幾分鐘升起（這個時間可以在偏好設定中變更）。

為什麼桌子沒有在我的會議時移動？

請確認相關功能是否已開啟（Stand during meetings）、會議是否符合上述規則，以及桌子是否已連線。如果你在會議期間自行降下了桌子，Standup 就不會在這場會議中再次升起它。

桌子移動前的小小提醒動作是什麼？

在自動移動之前，桌子會朝即將前進的方向輕輕晃動兩下，再等待一秒，因此絕不會毫無預警就移動。你可以在偏好設定的Nudge the desk before it moves中關閉這項功能。你自己手動觸發的移動則一律會立即執行。

通話偵測會做什麼，我的音訊會被錄下來嗎？

如果你開啟Keep raised while on a call，當會議應用程式仍在使用麥克風或喇叭時，桌子會在預定結束時間之後繼續保持升起狀態，並在其安靜下來後不久降下。Standup 只能得知是否有應用程式正在使用音訊，以及是哪個應用程式——它絕不會錄製或存取任何音訊或視訊內容，也不會請求麥克風或相機使用權限。

桌子停在比預設高度稍低或稍高的位置

Standup 會學習你的桌子在停止後還會多滑動多少距離，並在幾次移動後自動修正。如果誤差仍持續超過約半公分，請把兩個高度數值告訴我們。

我可以用腳本或「捷徑」控制桌子嗎？

可以。Standup 能辨識以下 AppleScript 指令：

tell application "Standup" to move desk "stand"    -- 或 "sit"、"up"、"down"
tell application "Standup" to set desk height "120cm"  -- 或 "48in"，也可以直接寫 "80"

在「捷徑」中加入一個執行 AppleScript動作，並使用上述任一行內容。macOS 只會在第一次使用時詢問是否允許控制 Standup。

會議提早結束了——桌子能更快降下嗎？

可以，只要開啟了Keep raised while on a call。當會議應用程式的麥克風與喇叭在預定結束時間之前安靜下來，通知就會詢問Meeting over? Lower the desk?。如果已過會議過半時間，會立即詢問；如果還在會議前半段，則會先等待兩分鐘的安靜狀態，以防只是連線暫時中斷。每場會議只會詢問一次，而且只在桌子處於升起狀態時才會詢問。

Standup 能切換 Home Assistant 場景嗎？（即將推出）

即將推出——目前的 App Store 版本尚未包含這項功能。屆時你可以在Preferences → Webhook中輸入 Webhook 網址。當桌子因會議而升起、以及之後降下時，Standup 會傳送一個帶有簡短 JSON 內容的 POST 請求：

{
  "app": "Standup",
  "event": "meeting_started",
  "source": "calendar",
  "meeting": "Weekly sync",
  "desk": "stand",
  "height_cm": 110.2,
  "timestamp": "2026-10-01T09:58:00Z"
}

event 為 meeting_started 或 meeting_ended，source 為 calendar 或 unplanned_call。自行移動桌子時不會傳送任何內容。Send test 按鈕可用於檢查連線是否正常。

在 Home Assistant 中，建立一個使用 Webhook 觸發器的自動化，並讓 Standup 指向 http://homeassistant.local:8123/api/webhook/standup：

alias: Standup meetings
triggers:
  - trigger: webhook
    webhook_id: standup
    allowed_methods: [POST]
    local_only: true
actions:
  - choose:
      - conditions: "{{ trigger.json.event == 'meeting_started' }}"
        sequence:
          - action: scene.turn_on
            target: { entity_id: scene.office_meeting }
      - conditions: "{{ trigger.json.event == 'meeting_ended' }}"
        sequence:
          - action: scene.turn_on
            target: { entity_id: scene.office_focus }
如何用「Send test」測試我的 Home Assistant 場景？（即將推出）

預設情況下，Send test 只會檢查連線——它傳送的是 "event": "test"，並不會開始一場會議。若要把這個按鈕當成會議場景的開關使用，可以讓 Webhook 驅動一個輔助實體（input_boolean），再把場景連結到該輔助實體上。這樣第一次測試會開啟場景，第二次測試則會關閉場景並還原燈光。請將以下內容放入一個套件中（例如 packages/standup.yaml），並依你的環境調整燈光部分：

input_boolean:
  standup_meeting:
    name: "Standup meeting"

automation:
  - alias: "Standup - webhook"
    mode: queued
    triggers:
      - trigger: webhook
        webhook_id: standup-YOUR-RANDOM-ID
        allowed_methods: [POST]
        local_only: false
    actions:
      - choose:
          - conditions: "{{ trigger.json.event == 'meeting_started' }}"
            sequence:
              - action: input_boolean.turn_on
                target: { entity_id: input_boolean.standup_meeting }
          - conditions: "{{ trigger.json.event == 'meeting_ended' }}"
            sequence:
              - action: input_boolean.turn_off
                target: { entity_id: input_boolean.standup_meeting }
          # "Send test" switches the meeting scene on, the next test switches it off
          - conditions: "{{ trigger.json.event == 'test' }}"
            sequence:
              - action: input_boolean.toggle
                target: { entity_id: input_boolean.standup_meeting }

  - alias: "Standup - meeting scene"
    triggers:
      - trigger: state
        entity_id: input_boolean.standup_meeting
        from: "off"
        to: "on"
    actions:
      # Remember the lights first, so they can be restored afterwards
      - action: scene.create
        data:
          scene_id: standup_before_meeting
          snapshot_entities: [light.living_room, light.hallway, light.desk_lamp]
      - action: light.turn_off
        target: { entity_id: [light.living_room, light.hallway] }
      - action: light.turn_on
        target: { entity_id: light.desk_lamp }

  - alias: "Standup - after the meeting"
    triggers:
      - trigger: state
        entity_id: input_boolean.standup_meeting
        from: "on"
        to: "off"
    conditions:
      - condition: template
        value_template: "{{ states.scene.standup_before_meeting is not none }}"
    actions:
      - action: scene.turn_on
        target: { entity_id: scene.standup_before_meeting }

小提示：

  • 如果 Home Assistant 可從網際網路存取，請使用一個夠長且隨機的 webhook_id——這個網址本身就是唯一的防護措施。
  • 請勿用狀態 unknown 作為判斷已儲存場景的條件：由 scene.create 建立的場景在被使用之前會一直維持 unknown 狀態，這樣的條件會讓燈光永遠無法還原。
  • 先點擊一次Send test，等場景生效後再點擊第二次。快速連續多次點擊可能會讓場景記住已經熄滅的燈光狀態。
  • 編輯完套件後，請重新載入自動化與輔助實體（或重新啟動 Home Assistant）。
我可以用鍵盤快速鍵移動桌子嗎？

可以，透過「捷徑」應用程式即可實現。請為每個動作各建立一個捷徑：

  1. 開啟捷徑，新建一個捷徑，例如「桌子：站立」。
  2. 加入一個執行 AppleScript動作，內容為 tell application "Standup" to move desk "stand"。其他捷徑則使用 "sit"、"up" 或 "down"。
  3. 開啟該捷徑的詳細資訊（ⓘ），選擇新增鍵盤快速鍵並按下想要的組合鍵，例如上/下用 ⌃⌥↑ / ⌃⌥↓，站立/坐下用 ⌃⌥S / ⌃⌥D。
  4. 第一次使用時，請允許「捷徑」控制 Standup。

這些快速鍵在任何應用程式中都能使用。up 與 down 每按一次會讓桌子移動約 1 公分；按住按鍵並不會讓它持續移動。

如何讓 Standup 在登入時啟動，或將其結束？

從彈出面板中的「…」選單開啟Preferences，並開啟Open at login。要結束應用程式，請從同一個選單中選擇Quit。
