지원

자주 묻는 질문에 대한 답변입니다. 그래도 해결되지 않나요? e-mail로 문의해 주세요.

책상을 처음 연결하려면 어떻게 하나요?
  1. 책상을 다른 기기에서 연결 해제하세요. 예를 들어 휴대폰의 책상 전용 앱을 종료합니다. 책상은 한 번에 하나의 기기와만 통신합니다.
  2. 페어링 모드를 켭니다. 책상 컨트롤러의 블루투스 버튼을 약 3초간 눌러 파란 불이 깜박이기 시작할 때까지 기다립니다.
  3. Standup을 열고 macOS가 블루투스 접근을 요청하면 허용합니다.
  4. Standup이 자동으로 책상을 찾아 연결합니다. 팝오버에 "Connecting…"이 표시된 후 책상 이름이 나타납니다. Mac에서 별도의 페어링 단계는 필요하지 않습니다.

이후에는 앱이 실행될 때마다, 그리고 Mac이 잠에서 깨어난 뒤에 Standup이 자동으로 다시 연결합니다.

Standup이 책상을 찾지 못해요

다음 순서대로 시도해 보세요:

  1. 책상에 연결된 다른 앱(휴대폰 앱이나 다른 Mac)을 종료하세요. 책상은 한 번에 하나의 기기와만 통신합니다.
  2. 시스템 설정 → 개인정보 보호 및 보안 → 블루투스에서 Standup의 블루투스 접근을 허용하세요.
  3. 블루투스에 표시되는 책상 이름에 여전히 "Desk"라는 단어가 포함되어 있는지 확인하세요.
  4. 페어링 모드를 켭니다: 컨트롤러의 블루투스 버튼을 약 3초간 눌러 불빛이 깜박일 때까지 기다립니다.
  5. 책상을 초기화하세요: 책상을 끝까지 내리고, 내리기 버튼을 눌러 책상이 한 번 아래로 내려갔다 올라올 때까지 기다립니다. 그다음 컨트롤러의 블루투스 버튼을 불빛이 깜박일 때까지 눌러준 뒤 Standup을 다시 엽니다.
Outlook 회의는 어떻게 사용하나요?

Standup은 macOS의 캘린더를 읽습니다. 시스템 설정 → 인터넷 계정에서 Outlook, Exchange 또는 Microsoft 365 계정을 추가하고 해당 계정의 캘린더가 켜져 있는지 확인하세요. 그러면 계정이 캘린더 앱에 표시되고 Standup도 그 회의를 인식합니다. Standup이 캘린더 접근을 요청하면 허용해 주세요.

어떤 회의일 때 책상이 올라가나요?

다른 참석자가 있고, URL·장소·메모 중 하나에 온라인 회의 링크(Teams, Meet, Zoom, Webex, Whereby 또는 GoToMeeting)가 포함되어 있으며, 사용자가 주최했거나 참석을 수락한 회의입니다. 종일 일정, 취소됨, 거절함, 미정, 응답 없음으로 표시된 일정과 "일정 없음(free)"으로 표시된 일정은 무시됩니다. 책상은 시작 몇 분 전부터 올라가기 시작합니다(이 시간은 환경설정에서 바꿀 수 있습니다).

왜 내 회의에서는 책상이 움직이지 않았나요?

해당 기능이 켜져 있는지(Stand during meetings), 회의가 위 조건을 충족하는지, 책상이 연결되어 있는지 확인하세요. 회의 중에 직접 책상을 내렸다면, Standup은 그 회의에서 다시 책상을 올리지 않습니다.

책상이 움직이기 전의 작은 예고 동작은 무엇인가요?

자동으로 움직이기 전에 책상은 이동할 방향으로 두 번 살짝 흔들린 뒤 1초를 기다리므로, 예고 없이 움직이는 일은 없습니다. 환경설정의 Nudge the desk before it moves에서 이 기능을 끌 수 있습니다. 직접 조작해서 움직일 때는 항상 즉시 이동합니다.

통화 감지는 무엇을 하며, 제 오디오가 녹음되나요?

Keep raised while on a call을 켜면, 예정된 종료 시간이 지나도 회의 앱이 마이크나 스피커를 계속 사용하는 동안 책상이 올라간 상태로 유지되고, 사용이 멈추면 잠시 후 내려갑니다. Standup은 어떤 앱이 오디오를 사용 중인지만 확인할 뿐, 오디오나 영상을 녹음하거나 접근하는 일은 전혀 없으며 마이크나 카메라 사용 권한을 요청하지도 않습니다.

책상이 프리셋 높이보다 조금 못 미치거나 조금 지나쳐서 멈춰요

Standup은 책상이 정지 후 얼마나 더 움직이는지를 학습해 몇 번의 이동 후 스스로 보정합니다. 그래도 오차가 약 0.5cm 이상 계속된다면, 두 높이 값을 적어 문의해 주세요.

스크립트나 단축어로 책상을 제어할 수 있나요?

네. Standup은 다음 AppleScript 명령을 이해합니다:

tell application "Standup" to move desk "stand"    -- 또는 "sit", "up", "down"
tell application "Standup" to set desk height "120cm"  -- 또는 "48in", 혹은 그냥 "80"

단축어 앱에서 위 줄 중 하나를 사용하는 AppleScript 실행 동작을 추가하세요. macOS는 Standup을 제어할 권한을 한 번만 확인합니다.

회의가 일찍 끝났어요 — 책상을 더 빨리 내릴 수 있나요?

네, Keep raised while on a call이 켜져 있다면 가능합니다. 회의 앱의 마이크와 스피커가 예정된 종료 시간보다 먼저 조용해지면, 알림이 Meeting over? Lower the desk?라고 묻습니다. 회의 후반이라면 즉시 묻고, 전반이라면 연결이 잠시 끊겼을 가능성을 고려해 2분간 조용한 상태가 이어진 뒤에 묻습니다. 회의당 한 번만, 그리고 책상이 올라가 있는 동안에만 묻습니다.

Standup으로 Home Assistant 장면을 전환할 수 있나요? (출시 예정)

출시 예정 — 현재 App Store 버전에는 아직 포함되어 있지 않습니다. Preferences → Webhook에서 웹훅 URL을 입력할 수 있게 됩니다. 회의를 위해 책상이 올라갈 때와 이후 내려갈 때, Standup은 다음과 같은 작은 JSON 본문을 담아 POST를 전송합니다:

{
  "app": "Standup",
  "event": "meeting_started",
  "source": "calendar",
  "meeting": "Weekly sync",
  "desk": "stand",
  "height_cm": 110.2,
  "timestamp": "2026-10-01T09:58:00Z"
}

event는 meeting_started 또는 meeting_ended이고, source는 calendar 또는 unplanned_call입니다. 직접 책상을 움직이면 아무것도 전송되지 않습니다. Send test 버튼으로 연결을 확인할 수 있습니다.

Home Assistant에서는 웹훅 트리거를 사용하는 자동화를 만들고, Standup에는 http://homeassistant.local:8123/api/webhook/standup 주소를 입력하세요:

alias: Standup meetings
triggers:
  - trigger: webhook
    webhook_id: standup
    allowed_methods: [POST]
    local_only: true
actions:
  - choose:
      - conditions: "{{ trigger.json.event == 'meeting_started' }}"
        sequence:
          - action: scene.turn_on
            target: { entity_id: scene.office_meeting }
      - conditions: "{{ trigger.json.event == 'meeting_ended' }}"
        sequence:
          - action: scene.turn_on
            target: { entity_id: scene.office_focus }
"Send test"로 Home Assistant 장면을 테스트하려면 어떻게 하나요? (출시 예정)

기본적으로 Send test는 연결만 확인하며 "event": "test"를 전송할 뿐, 회의를 시작시키지 않습니다. 이 버튼을 회의 장면의 켜기/끄기 스위치로 사용하려면, 웹훅이 헬퍼(input_boolean)를 제어하도록 하고 그 헬퍼에 장면을 연결하세요. 그러면 첫 번째 테스트에서 장면이 켜지고, 두 번째 테스트에서 꺼지며 조명이 원래 상태로 복원됩니다. 이를 패키지(예: packages/standup.yaml)에 넣고 조명 부분을 환경에 맞게 조정하세요:

input_boolean:
  standup_meeting:
    name: "Standup meeting"

automation:
  - alias: "Standup - webhook"
    mode: queued
    triggers:
      - trigger: webhook
        webhook_id: standup-YOUR-RANDOM-ID
        allowed_methods: [POST]
        local_only: false
    actions:
      - choose:
          - conditions: "{{ trigger.json.event == 'meeting_started' }}"
            sequence:
              - action: input_boolean.turn_on
                target: { entity_id: input_boolean.standup_meeting }
          - conditions: "{{ trigger.json.event == 'meeting_ended' }}"
            sequence:
              - action: input_boolean.turn_off
                target: { entity_id: input_boolean.standup_meeting }
          # "Send test" switches the meeting scene on, the next test switches it off
          - conditions: "{{ trigger.json.event == 'test' }}"
            sequence:
              - action: input_boolean.toggle
                target: { entity_id: input_boolean.standup_meeting }

  - alias: "Standup - meeting scene"
    triggers:
      - trigger: state
        entity_id: input_boolean.standup_meeting
        from: "off"
        to: "on"
    actions:
      # Remember the lights first, so they can be restored afterwards
      - action: scene.create
        data:
          scene_id: standup_before_meeting
          snapshot_entities: [light.living_room, light.hallway, light.desk_lamp]
      - action: light.turn_off
        target: { entity_id: [light.living_room, light.hallway] }
      - action: light.turn_on
        target: { entity_id: light.desk_lamp }

  - alias: "Standup - after the meeting"
    triggers:
      - trigger: state
        entity_id: input_boolean.standup_meeting
        from: "on"
        to: "off"
    conditions:
      - condition: template
        value_template: "{{ states.scene.standup_before_meeting is not none }}"
    actions:
      - action: scene.turn_on
        target: { entity_id: scene.standup_before_meeting }

참고:

  • Home Assistant가 인터넷에서 접근 가능하다면 길고 무작위한 webhook_id를 사용하세요 — URL 자체가 유일한 보호 장치입니다.
  • 저장된 장면의 상태가 unknown인지 확인하는 조건은 사용하지 마세요. scene.create로 만든 장면은 사용되기 전까지 unknown 상태로 남아 있으므로, 그런 조건을 걸면 조명이 다시는 복원되지 않습니다.
  • Send test를 한 번 클릭하고 장면이 반영되기를 기다린 뒤 다시 클릭하세요. 빠르게 여러 번 클릭하면 이미 꺼진 조명 상태를 장면이 그대로 기억해버릴 수 있습니다.
  • 패키지를 수정한 뒤에는 자동화와 헬퍼를 다시 불러오세요(또는 Home Assistant를 재시작하세요).
키보드 단축키로 책상을 움직일 수 있나요?

네, 단축어 앱을 사용하면 가능합니다. 각 동작마다 단축어를 하나씩 만드세요:

  1. 단축어를 열고 새 단축어를 만듭니다. 예: "책상: 서기".
  2. tell application "Standup" to move desk "stand"를 사용하는 AppleScript 실행 동작을 추가합니다. 다른 단축어에는 "sit", "up", "down"을 사용하세요.
  3. 단축어 세부 정보(ⓘ)를 열고 키보드 단축키 추가를 선택한 뒤 원하는 키를 누릅니다. 예: 위/아래는 ⌃⌥↑ / ⌃⌥↓, 서기·앉기는 ⌃⌥S / ⌃⌥D.
  4. 처음 사용할 때 단축어 앱이 Standup을 제어하도록 허용하세요.

이 단축키는 어떤 앱에서든 작동합니다. up과 down은 한 번 누를 때마다 책상을 약 1cm씩 움직입니다. 키를 누르고 있어도 계속 움직이지는 않습니다.

Standup을 로그인 시 자동 실행하거나 종료하려면 어떻게 하나요?

팝오버의 "…" 메뉴에서 Preferences를 열고 Open at login을 켜세요. 앱을 종료하려면 같은 메뉴에서 Quit을 선택하세요.
