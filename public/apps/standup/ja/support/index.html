サポート

よくある質問への回答です。解決しない場合はe-mailまでご連絡ください。

デスクを初めて接続するには?
  1. デスクを他のデバイスから切断してください。たとえば、スマートフォンのデスク用アプリを終了します。デスクは一度に1台のデバイスとしか通信できません。
  2. ペアリングモードをオンにします。デスクのコントローラーにあるBluetoothボタンを約3秒間押し続け、青いランプが点滅し始めるまで待ちます。
  3. Standupを開き、macOSからBluetoothの許可を求められたら許可します。
  4. Standupが自動的にデスクを見つけて接続します。ポップオーバーには「Connecting…」と表示され、続いてデスクの名前が表示されます。Mac側で個別のペアリング操作は必要ありません。

その後は、起動時やMacがスリープから復帰したときに、Standupが自動的に再接続します。

Standupがデスクを見つけられない

次の手順を順番に試してください:

  1. デスクに接続している他のアプリ(スマートフォンのアプリや別のMacなど)を終了します。デスクは一度に1台のデバイスとしか通信できません。
  2. システム設定→プライバシーとセキュリティ→BluetoothでStandupのBluetoothを許可します。
  3. Bluetoothに表示されるデスクの名前に「Desk」という単語が含まれているか確認します。
  4. ペアリングモードをオンにします。コントローラーのBluetoothボタンを約3秒間押し続け、ランプが点滅するまで待ちます。
  5. デスクをリセットします。デスクを一番下まで下げ、下げるボタンを押し続けてデスクが一度下がってから上がるまで待ちます。その後コントローラーのBluetoothボタンをランプが点滅するまで押し続け、Standupを再度開きます。
Outlookの会議を使うには?

StandupはmacOSの「カレンダー」を読み取ります。システム設定→インターネットアカウントでOutlook、Exchange、またはMicrosoft 365のアカウントを追加し、そのアカウントで「カレンダー」がオンになっていることを確認してください。アカウントが「カレンダー」アプリに表示されるようになると、Standupもその会議を認識します。Standupからカレンダーへのアクセスを求められたら許可してください。

どの会議でデスクが上がりますか?

他の参加者がいて、URL・場所・メモのいずれかにオンライン会議のリンク(Teams、Meet、Zoom、Webex、Whereby、GoToMeeting)が含まれ、自分が主催または参加を承諾した会議です。終日の予定、キャンセル済み、辞退、仮承諾、未回答の予定、および「空き時間」として設定された予定は対象外です。デスクは開始の数分前から上がり始めます(この時間は環境設定で変更できます)。

会議のときにデスクが動かなかったのはなぜですか?

Stand during meetingsが有効になっていること、会議が上記の条件を満たしていること、デスクが接続されていることを確認してください。会議中に自分でデスクを下げた場合、Standupはその会議では再度デスクを上げません。

デスクが動く前の小さな予告動作は何ですか?

自動で動く前に、デスクはこれから進む方向へ2回小さく揺れ、1秒待ちます。これにより予告なしに動き出すことはありません。環境設定のNudge the desk before it movesでオフにできます。自分で操作したときの動作は常に即座に行われます。

通話検知は何をしますか?音声は録音されますか?

Keep raised while on a callを有効にすると、予定終了時刻を過ぎても会議アプリがマイクまたはスピーカーを使用している間はデスクが上がったままになり、使用が止まるとすぐに下がります。Standupが確認するのはどのアプリが音声を使用しているかだけで、音声や映像を録音・アクセスすることは一切なく、マイクやカメラへのアクセス許可も求めません。

デスクがプリセットの高さより少し手前または先で止まる

Standupは、デスクが停止後にどのくらい余分に動くかを学習し、何度か動かすうちに自動で補正します。それでも誤差が0.5cm以上残る場合は、該当する2つの高さを記載してご連絡ください。

スクリプトやショートカットからデスクを操作できますか?

できます。Standupは次のAppleScriptコマンドに対応しています:

tell application "Standup" to move desk "stand"    -- または "sit"、"up"、"down"
tell application "Standup" to set desk height "120cm"  -- または "48in"、あるいは単に "80"

「ショートカット」アプリで、上記のいずれかの行を使ったAppleScriptを実行アクションを追加してください。macOSはStandupを操作する許可を一度だけ確認します。

会議が早く終わった場合、デスクを早く下げられますか?

はい、Keep raised while on a callがオンの場合に可能です。予定終了時刻より前に会議アプリのマイクとスピーカーの使用が止まると、通知でMeeting over? Lower the desk?と確認します。会議の後半であればすぐに確認し、前半の場合は接続が一時的に切れた可能性も考えて2分間の静寂を待ってから確認します。確認は会議ごとに1回だけ、かつデスクが上がっている間だけ行われます。

StandupでHome Assistantのシーンを切り替えられますか?(近日公開)

近日公開 — 現行のApp Store版にはまだ搭載されていません。Preferences → WebhookでWebhookのURLを入力できるようになります。会議のためにデスクが上がるとき、そしてその後下がるときに、Standupは小さなJSON本文を含むPOSTを送信します:

{
  "app": "Standup",
  "event": "meeting_started",
  "source": "calendar",
  "meeting": "Weekly sync",
  "desk": "stand",
  "height_cm": 110.2,
  "timestamp": "2026-10-01T09:58:00Z"
}

eventはmeeting_startedまたはmeeting_ended、sourceはcalendarまたはunplanned_callです。自分でデスクを動かした場合は何も送信されません。Send testボタンで接続を確認できます。

Home Assistantでは、Webhookトリガーを使ったオートメーションを作成し、Standup側にhttp://homeassistant.local:8123/api/webhook/standupを指定してください:

alias: Standup meetings
triggers:
  - trigger: webhook
    webhook_id: standup
    allowed_methods: [POST]
    local_only: true
actions:
  - choose:
      - conditions: "{{ trigger.json.event == 'meeting_started' }}"
        sequence:
          - action: scene.turn_on
            target: { entity_id: scene.office_meeting }
      - conditions: "{{ trigger.json.event == 'meeting_ended' }}"
        sequence:
          - action: scene.turn_on
            target: { entity_id: scene.office_focus }
「Send test」でHome Assistantのシーンを試すには?(近日公開)

既定ではSend testは接続確認のみを行い、"event": "test"を送信します。これは会議の開始を意味しません。このボタンを会議シーンのオン/オフ切り替えとして使うには、Webhookでヘルパー(input_boolean)を操作し、そのヘルパーにシーンを紐づけます。最初のテストでシーンがオンになり、2回目のテストでオフになって照明が元の状態に戻ります。これをパッケージ(例: packages/standup.yaml)に記述し、照明の部分をご自身の環境に合わせて調整してください:

input_boolean:
  standup_meeting:
    name: "Standup meeting"

automation:
  - alias: "Standup - webhook"
    mode: queued
    triggers:
      - trigger: webhook
        webhook_id: standup-YOUR-RANDOM-ID
        allowed_methods: [POST]
        local_only: false
    actions:
      - choose:
          - conditions: "{{ trigger.json.event == 'meeting_started' }}"
            sequence:
              - action: input_boolean.turn_on
                target: { entity_id: input_boolean.standup_meeting }
          - conditions: "{{ trigger.json.event == 'meeting_ended' }}"
            sequence:
              - action: input_boolean.turn_off
                target: { entity_id: input_boolean.standup_meeting }
          # "Send test" switches the meeting scene on, the next test switches it off
          - conditions: "{{ trigger.json.event == 'test' }}"
            sequence:
              - action: input_boolean.toggle
                target: { entity_id: input_boolean.standup_meeting }

  - alias: "Standup - meeting scene"
    triggers:
      - trigger: state
        entity_id: input_boolean.standup_meeting
        from: "off"
        to: "on"
    actions:
      # Remember the lights first, so they can be restored afterwards
      - action: scene.create
        data:
          scene_id: standup_before_meeting
          snapshot_entities: [light.living_room, light.hallway, light.desk_lamp]
      - action: light.turn_off
        target: { entity_id: [light.living_room, light.hallway] }
      - action: light.turn_on
        target: { entity_id: light.desk_lamp }

  - alias: "Standup - after the meeting"
    triggers:
      - trigger: state
        entity_id: input_boolean.standup_meeting
        from: "on"
        to: "off"
    conditions:
      - condition: template
        value_template: "{{ states.scene.standup_before_meeting is not none }}"
    actions:
      - action: scene.turn_on
        target: { entity_id: scene.standup_before_meeting }

ヒント:

  • Home Assistantがインターネットからアクセス可能な場合は、長くランダムなwebhook_idを使用してください — URL自体が唯一の防御になります。
  • 保存したシーンの状態がunknownかどうかを確認条件にしないでください。scene.createで作成したシーンは使用されるまでunknownのままなので、そのような条件を付けると照明が二度と元に戻らなくなります。
  • Send testを1回クリックしてシーンの反映を待ち、それから再度クリックしてください。短時間に何度もクリックすると、すでに消灯した照明の状態をシーンが記憶してしまう場合があります。
  • パッケージを編集した後は、オートメーションとヘルパーを再読み込みするか、Home Assistantを再起動してください。
キーボードショートカットでデスクを動かせますか?

はい、「ショートカット」アプリで可能です。動作ごとに1つのショートカットを作成します:

  1. ショートカットを開き、新しいショートカットを作成します。例: 「デスク: 立つ」。
  2. tell application "Standup" to move desk "stand"を使ったAppleScriptを実行アクションを追加します。他のショートカットには"sit"、"up"、"down"を使用してください。
  3. ショートカットの詳細(ⓘ)を開き、キーボードショートカットを追加を選んでキーを押します。例: 上下には⌃⌥↑ / ⌃⌥↓、立つ・座るには⌃⌥S / ⌃⌥Dなど。
  4. 初回使用時に、「ショートカット」がStandupを操作することを許可してください。

このショートカットはどのアプリからでも使用できます。upとdownは1回の押下でデスクを約1cm動かします。キーを押し続けても動き続けることはありません。

Standupをログイン時に起動したり、終了したりするには?

ポップオーバーの「…」メニューからPreferencesを開き、Open at loginをオンにしてください。アプリを終了するには、同じメニューからQuitを選択します。
