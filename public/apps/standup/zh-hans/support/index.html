支持

以下是常见问题的解答。仍未解决？请发送电子邮件与我们联系。

如何第一次连接我的桌子？
  1. 先断开桌子与其他设备的连接——例如关闭手机上的桌子控制应用。桌子一次只能与一台设备通信。
  2. 开启配对模式：按住桌子控制器上的蓝牙按钮约 3 秒，直到蓝色指示灯开始闪烁。
  3. 打开 Standup，并在 macOS 询问时允许使用蓝牙。
  4. Standup 会自动找到桌子并完成连接——弹出面板会先显示“Connecting…”，随后显示桌子的名称。Mac 上无需任何额外的配对步骤。

此后，每次启动应用或 Mac 唤醒后，Standup 都会自动重新连接。

Standup 找不到我的桌子

请按顺序尝试以下步骤：

  1. 关闭所有其他已连接到桌子的应用（手机应用、另一台 Mac 等）。桌子一次只能与一台设备通信。
  2. 在系统设置 → 隐私与安全性 → 蓝牙中允许 Standup 使用蓝牙。
  3. 确认蓝牙中显示的桌子名称仍包含“Desk”一词。
  4. 开启配对模式：按住控制器上的蓝牙按钮约 3 秒，直到指示灯闪烁。
  5. 重置桌子：将桌子降到最低位置，按住降下按钮直到桌子先降后升，然后按住控制器上的蓝牙按钮直到指示灯闪烁，再重新打开 Standup。
如何使用 Outlook 会议？

Standup 读取的是 macOS 的“日历”。请在系统设置 → 互联网账户中添加你的 Outlook、Exchange 或 Microsoft 365 账户，并确认已为该账户开启“日历”。之后该账户会出现在“日历”应用中，Standup 也就能识别其中的会议。当 Standup 请求日历访问权限时，请予以允许。

哪些会议会让桌子升起？

有其他参会者、在网址、地点或备注中包含线上会议链接（Teams、Meet、Zoom、Webex、Whereby 或 GoToMeeting），且是你组织或已接受的会议。全天事件、已取消、已拒绝、暂定或未回复的邀请，以及标记为“空闲”的事件都会被忽略。桌子会在开始前几分钟升起（可在偏好设置中更改提前时间）。

为什么桌子没有在我的会议时移动？

请检查相关功能是否已开启（Stand during meetings）、会议是否符合上述规则，以及桌子是否已连接。如果你在会议期间自己降下了桌子，Standup 不会在该会议中再次升起它。

桌子移动前的小小提醒动作是什么？

在自动移动之前，桌子会朝即将移动的方向轻轻晃动两下，再等待一秒，因此绝不会毫无预警地移动。你可以在偏好设置的Nudge the desk before it moves中关闭此功能。手动触发的移动始终会立即执行。

通话检测会做什么，我的音频会被录制吗？

如果你开启Keep raised while on a call，当会议应用仍在使用麦克风或扬声器时，桌子会在预定结束时间之后继续保持升起状态，并在其安静下来后不久降下。Standup 只能得知是否有应用正在使用音频以及是哪个应用——它绝不会录制或访问任何音频或视频内容，也不会请求麦克风或摄像头权限。

桌子停在比预设高度稍低或稍高的位置

Standup 会学习你的桌子在停止后还会多滑动多少距离，并在几次移动后自动修正。如果误差仍持续超过约半厘米，请把两个高度数值告诉我们。

我可以用脚本或“快捷指令”控制桌子吗？

可以。Standup 能识别以下 AppleScript 命令：

tell application "Standup" to move desk "stand"    -- 或 "sit"、"up"、"down"
tell application "Standup" to set desk height "120cm"  -- 或 "48in"，也可以直接写 "80"

在“快捷指令”中添加一个运行 AppleScript操作，并使用上述任意一行代码。macOS 只会在首次使用时询问是否允许控制 Standup。

会议提前结束了——桌子能更快降下吗？

可以，只要开启了Keep raised while on a call。当会议应用的麦克风和扬声器在预定结束时间之前安静下来，通知会询问Meeting over? Lower the desk?。如果已过会议过半时间，会立即询问；如果还在会议前半段，则会先等待两分钟的安静状态，以防只是连接暂时中断。每次会议只会询问一次，且仅在桌子处于升起状态时才会询问。

Standup 能切换 Home Assistant 场景吗？（即将推出）

即将推出——目前的 App Store 版本尚未包含此功能。届时你可以在Preferences → Webhook中输入 Webhook 网址。当桌子因会议而升起、以及之后降下时，Standup 会发送一个带有简短 JSON 内容的 POST 请求：

{
  "app": "Standup",
  "event": "meeting_started",
  "source": "calendar",
  "meeting": "Weekly sync",
  "desk": "stand",
  "height_cm": 110.2,
  "timestamp": "2026-10-01T09:58:00Z"
}

event 为 meeting_started 或 meeting_ended，source 为 calendar 或 unplanned_call。手动移动桌子不会发送任何内容。Send test 按钮可用于检查连接是否正常。

在 Home Assistant 中，创建一个使用 Webhook 触发器的自动化，并让 Standup 指向 http://homeassistant.local:8123/api/webhook/standup：

alias: Standup meetings
triggers:
  - trigger: webhook
    webhook_id: standup
    allowed_methods: [POST]
    local_only: true
actions:
  - choose:
      - conditions: "{{ trigger.json.event == 'meeting_started' }}"
        sequence:
          - action: scene.turn_on
            target: { entity_id: scene.office_meeting }
      - conditions: "{{ trigger.json.event == 'meeting_ended' }}"
        sequence:
          - action: scene.turn_on
            target: { entity_id: scene.office_focus }
如何用“Send test”测试我的 Home Assistant 场景？（即将推出）

默认情况下，Send test 只会检查连接——它发送的是 "event": "test"，并不会开始一次会议。要把这个按钮当作会议场景的开/关开关使用，可以让 Webhook 驱动一个辅助实体（input_boolean），再把场景关联到该辅助实体上。这样第一次测试会打开场景，第二次测试则会关闭场景并恢复灯光。请将以下内容放入一个软件包中（例如 packages/standup.yaml），并根据需要调整灯光部分：

input_boolean:
  standup_meeting:
    name: "Standup meeting"

automation:
  - alias: "Standup - webhook"
    mode: queued
    triggers:
      - trigger: webhook
        webhook_id: standup-YOUR-RANDOM-ID
        allowed_methods: [POST]
        local_only: false
    actions:
      - choose:
          - conditions: "{{ trigger.json.event == 'meeting_started' }}"
            sequence:
              - action: input_boolean.turn_on
                target: { entity_id: input_boolean.standup_meeting }
          - conditions: "{{ trigger.json.event == 'meeting_ended' }}"
            sequence:
              - action: input_boolean.turn_off
                target: { entity_id: input_boolean.standup_meeting }
          # "Send test" switches the meeting scene on, the next test switches it off
          - conditions: "{{ trigger.json.event == 'test' }}"
            sequence:
              - action: input_boolean.toggle
                target: { entity_id: input_boolean.standup_meeting }

  - alias: "Standup - meeting scene"
    triggers:
      - trigger: state
        entity_id: input_boolean.standup_meeting
        from: "off"
        to: "on"
    actions:
      # Remember the lights first, so they can be restored afterwards
      - action: scene.create
        data:
          scene_id: standup_before_meeting
          snapshot_entities: [light.living_room, light.hallway, light.desk_lamp]
      - action: light.turn_off
        target: { entity_id: [light.living_room, light.hallway] }
      - action: light.turn_on
        target: { entity_id: light.desk_lamp }

  - alias: "Standup - after the meeting"
    triggers:
      - trigger: state
        entity_id: input_boolean.standup_meeting
        from: "on"
        to: "off"
    conditions:
      - condition: template
        value_template: "{{ states.scene.standup_before_meeting is not none }}"
    actions:
      - action: scene.turn_on
        target: { entity_id: scene.standup_before_meeting }

小提示：

  • 如果 Home Assistant 可从互联网访问，请使用一个长且随机的 webhook_id——这个网址本身就是唯一的防护手段。
  • 不要用状态 unknown 作为判断已保存场景的条件：由 scene.create 创建的场景在被使用之前会一直保持 unknown 状态，这样的条件会导致灯光永远无法恢复。
  • 先点击一次Send test，等待场景生效后再点击第二次。快速连续多次点击可能会让场景记录下已经熄灭的灯光状态。
  • 编辑完软件包后，请重新加载自动化与辅助实体（或重启 Home Assistant）。
我可以用键盘快捷键移动桌子吗？

可以，通过“快捷指令”应用实现。请为每个动作分别创建一个快捷指令：

  1. 打开快捷指令，新建一个快捷指令，例如“桌子：站立”。
  2. 添加一个运行 AppleScript操作，内容为 tell application "Standup" to move desk "stand"。其他快捷指令则使用 "sit"、"up" 或 "down"。
  3. 打开该快捷指令的详情（ⓘ），选择添加键盘快捷键并按下想要的组合键，例如上/下用 ⌃⌥↑ / ⌃⌥↓，站立/坐下用 ⌃⌥S / ⌃⌥D。
  4. 首次使用时，允许“快捷指令”控制 Standup。

这些快捷键在任何应用中都可以使用。up 和 down 每按一次会让桌子移动约 1 厘米；按住按键并不会让它持续移动。

如何让 Standup 在登录时启动，或将其退出？

从弹出面板中的“…”菜单打开Preferences，并开启Open at login。要关闭应用，请从同一菜单中选择Quit。
